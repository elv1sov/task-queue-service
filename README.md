# Task Queue Service

Сервис фоновых задач на Go. API принимает задачу и сразу возвращает её ID. Worker выполняет задачу в фоне, а результат можно получить отдельным HTTP-запросом.

## Как проходит задача

1. API проверяет входные данные и записывает задачу в PostgreSQL со статусом `pending`.
2. Worker берёт самую раннюю доступную задачу и переводит её в `running` одним SQL-запросом. Блокировка `FOR UPDATE SKIP LOCKED` позволяет другим обработчикам брать следующие задачи.
3. Worker выполняет операцию и сохраняет результат со статусом `completed` или ошибку со статусом `failed`.

Когда очередь пуста, Worker ждёт секунду перед следующим запросом. Все процессы используют одну базу. Количество обработчиков задаётся отдельно для каждого Worker. Параллельные задачи могут завершаться в другом порядке.

| Каталог | Назначение |
| --- | --- |
| `cmd/api` | HTTP-сервер на `net/http` |
| `cmd/worker` | Процесс фоновой обработки |
| `internal/config` | Чтение переменных окружения |
| `internal/handler` | Маршруты, проверка запросов, JSON-ответы |
| `internal/service` | Создание, проверка и выполнение задач |
| `internal/repository` | Хранение задач в PostgreSQL через pgx |
| `internal/model` | Поля задач и статусы |
| `migrations` | SQL для создания таблицы |
| `tests` | Тесты HTTP и бизнес-логики |

## Локальный запуск

Нужны Go 1.25 или новее, запущенный PostgreSQL и клиент `psql`. Создай в PostgreSQL пустую базу `task_queue` и роль с доступом к ней. Для миграции роль должна иметь право создавать таблицы в схеме. Выполняй команды из корня проекта.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `HTTP_PORT` | `8080` | Порт API, от 1 до 65535 |
| `DATABASE_URL` | Обязательна | Строка подключения PostgreSQL |
| `WORKER_CONCURRENCY` | `4` | Число обработчиков на Worker, от 1 до 128 |

Введи свою строку подключения в терминале Bash. В ней используются реальные имя роли, пароль и адрес, а специальные символы в пароле должны быть URL-кодированы.

```bash
read -rsp 'DATABASE_URL: ' DATABASE_URL
printf '\n'
export DATABASE_URL
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f migrations/001_create_tasks.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f migrations/002_pending_index.sql
go mod download
mkdir -p bin
go build -o bin/api ./cmd/api
go build -o bin/worker ./cmd/worker
```

Формат строки подключения — `postgres://USER:PASSWORD@127.0.0.1:5432/task_queue`. Для локального PostgreSQL без TLS добавь `?sslmode=disable`. Для новой базы выполни обе миграции в указанном порядке. Если таблица уже есть от предыдущей версии этого проекта, выполни только вторую миграцию. После остановки старых процессов новый Worker подхватит записи со статусом `pending`.

Запусти API в первом терминале:

```bash
./bin/api
```

Во втором терминале снова задай и экспортируй `DATABASE_URL`, затем запусти Worker:

```bash
WORKER_CONCURRENCY=4 ./bin/worker
```

Можно запустить ещё один Worker в третьем терминале. Ctrl+C или SIGTERM останавливает приём новых запросов или задач. API даёт текущим запросам время завершиться. Worker ждёт завершения уже извлечённых задач, затем закрывает соединения.

## HTTP API

### POST /api/tasks

```bash
curl -i http://localhost:8080/api/tasks \
  -H 'Content-Type: application/json' \
  -d '{"type":"uppercase","payload":{"text":"hello world"}}'
```

При успехе API возвращает `201 Created`, заголовок `Location: /api/tasks/{id}` и объект задачи в поле `data`. Статус в ответе отражает момент создания задачи.

| Тип | Пример payload | Пример result |
| --- | --- | --- |
| `uppercase` | `{"text":"hello world"}` | `{"text":"HELLO WORLD"}` |
| `count_words` | `{"text":"hello world"}` | `{"words":2}` |
| `sleep` | `{"seconds":2}` | `{"slept_seconds":2}` |

`count_words` считает последовательности символов, разделённые пробельными символами. Для `sleep` допустимо целое число от 0 до 30 включительно. Размер тела запроса ограничен 64 КиБ.

### GET /api/tasks/{id}

```bash
curl http://localhost:8080/api/tasks/1
```

Подставь ID из ответа на POST. При успехе код `200`. Пример завершённой задачи:

```json
{
  "data": {
    "id": 1,
    "type": "uppercase",
    "payload": {"text": "hello world"},
    "status": "completed",
    "result": {"text": "HELLO WORLD"},
    "error": null,
    "created_at": "2026-01-01T12:00:00Z",
    "updated_at": "2026-01-01T12:00:01Z"
  },
  "error": null
}
```

Если выполнение закончилось ошибкой, `data.status` будет `failed`, а текст ошибки появится в `data.error`.

### GET /api/tasks

```bash
curl 'http://localhost:8080/api/tasks?limit=5'
```

Код `200`. Поле `data` содержит массив задач по убыванию ID. По умолчанию возвращается до 20 задач. Параметр `limit` принимает число от 1 до 100.

### GET /health

```bash
curl http://localhost:8080/health
```

API проверяет соединение с PostgreSQL. При успехе возвращает `200` и `{"data":{"status":"ok"},"error":null}`. Из результата можно узнать доступность зависимостей. Наличие запущенных Worker проверяется отдельно.

### Ошибки HTTP

Формат ошибки: `{"data":null,"error":"task not found"}`.

| Код | Причина |
| --- | --- |
| `400` | Некорректный JSON, тип, payload, ID или limit |
| `404` | Задача или маршрут отсутствует |
| `405` | Метод не поддерживается |
| `413` | Тело запроса превышает 64 КиБ |
| `503` | Не удалось выполнить операцию в PostgreSQL |

Повторный POST создаёт новую задачу с новым ID.

## Сбои и поведение очереди

- При ошибке соединения на старте процесс пишет причину в лог и завершается. Если PostgreSQL недоступен во время работы, API возвращает `503`, а Worker повторяет попытку через секунду.
- Ожидающие задачи остаются в PostgreSQL при остановке Worker. Запись в `running` может застрять после аварийной остановки Worker или ошибки сохранения результата. Автоматического возврата таких задач в очередь нет. Перед повторной отправкой проверь, завершился ли процесс, который взял задачу.
- API слушает все интерфейсы и рассчитан на локальную практику в доверенной сети. Аутентификация отсутствует.

## Тесты

```bash
go test ./...
go vet ./...
```

Тесты Worker проверяют сохранение результата при штатной остановке и обработку ошибок. Тесты HTTP работают через `httptest` и подставные зависимости. Для запуска тестов PostgreSQL не требуется.
